# Deployment

Every path below runs on free tiers end to end. Nothing here requires a paid plan or a credit card.

---

## What you need

| Piece | Free option | Notes |
|---|---|---|
| PostgreSQL | [Neon](https://neon.tech) · [Supabase](https://supabase.com) · Render Postgres | Neon has no expiry; Render's free database expires after 90 days |
| API | [Render](https://render.com) · [Railway](https://railway.app) · [Fly.io](https://fly.io) | Render free services sleep after ~15 min idle; first request then takes ~50s |
| Frontend | [Vercel](https://vercel.com) · [Netlify](https://netlify.com) · Render Static | Static build, no server needed |
| Language model | [Groq](https://console.groq.com/keys) · [Gemini](https://aistudio.google.com/apikey) · [OpenRouter](https://openrouter.ai/keys) | Entirely optional — see [Without a model](#without-a-model) |
| Email | [Resend](https://resend.com) | Optional; invoice delivery is skipped when unset |

## Option 1 — Render Blueprint (whole stack, one click)

[`render.yaml`](../render.yaml) declares the database, API and frontend.

1. Push this repository to GitHub.
2. Render → **New** → **Blueprint** → select the repository.
3. Render provisions all three and prompts for the values it cannot generate.
4. After the first deploy, set the two cross-service URLs (Render cannot compute these itself, because it has no way to prepend a scheme to a service host):

   | Service | Variable | Value |
   |---|---|---|
   | `workledger-api` | `CORS_ALLOWED_ORIGINS` | `https://workledger-web.onrender.com` |
   | `workledger-web` | `VITE_API_BASE_URL` | `https://workledger-api.onrender.com/api` |

5. Redeploy the frontend — Vite inlines `VITE_API_BASE_URL` at build time, so it needs a rebuild to take effect.

`JWT_SECRET` is generated by Render. `DATABASE_URL` is wired from the database automatically and converted to JDBC at startup.

## Option 2 — Split deploy (Vercel + Render + Neon)

The combination with no sleep on the frontend and no database expiry.

**1. Database — Neon**

Create a project, copy the connection string.

**2. API — Render web service**

New → Web Service → repository → Root Directory `Backend`, Runtime `Docker`.

```
SPRING_PROFILES_ACTIVE = prod
DATABASE_URL           = postgres://user:pass@ep-xxx.neon.tech/workledger?sslmode=require
JWT_SECRET             = <openssl rand -base64 48>
CORS_ALLOWED_ORIGINS   = https://your-app.vercel.app
```

`DATABASE_URL` in `postgres://` form is fine — [`DatabaseUrlEnvironmentPostProcessor`](../Backend/src/main/java/backend/WF/config/DatabaseUrlEnvironmentPostProcessor.java) converts it to JDBC and splits out the credentials before the datasource is built.

**3. Frontend — Vercel**

Import the repository, Root Directory `Frontend`. Vercel detects Vite; set one variable:

```
VITE_API_BASE_URL = https://your-api.onrender.com/api
```

Add `Frontend/vercel.json` so client-side routes resolve:

```json
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
```

## Option 3 — Docker Compose (local or any VPS)

```bash
cp .env.example .env     # set JWT_SECRET at minimum
docker compose up --build
```

Brings up PostgreSQL 16, the API, and the frontend behind nginx. The API waits on the database's health check, so Flyway never races an unready Postgres.

- App — http://localhost:3000
- API docs — http://localhost:8080/swagger-ui.html

## Environment variables

Full annotated list in [`.env.example`](../.env.example). The ones that matter:

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `DATABASE_URL` | one of these | — | `postgres://…`, converted at startup |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | one of these | localhost | JDBC parts; takes precedence over `DATABASE_URL` |
| `JWT_SECRET` | **yes** | dev placeholder | ≥ 32 chars; startup fails without a valid one |
| `CORS_ALLOWED_ORIGINS` | yes in prod | localhost dev ports | Comma-separated origins; never a wildcard |
| `SPRING_PROFILES_ACTIVE` | — | `dev` | Use `prod` when deployed |
| `PORT` | — | 8080 | Injected by most hosts; honoured automatically |
| `AI_ENABLED` | — | `false` | Master switch for every model call |
| `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` | — | Groq defaults | Any OpenAI-compatible endpoint |
| `RESEND_API_KEY` / `RESEND_FROM_EMAIL` | — | — | Invoice email; skipped when unset |
| `VITE_API_BASE_URL` | build-time | `/api` | Only for split deploys |

## Without a model

`AI_ENABLED=false` is the default and a supported production configuration:

- **Contract extraction** runs on the pattern engine — lower recall on unusual wording, exact citations.
- **Invoice auditing** is unchanged. It was always deterministic; the model only ever wrote explanatory prose.
- **Audit summaries** are templated rather than model-written, and say the same thing in fewer words.

Turning it on costs nothing on any of the listed providers:

```bash
AI_ENABLED=true
AI_API_KEY=gsk_...
AI_BASE_URL=https://api.groq.com/openai
AI_MODEL=llama-3.3-70b-versatile
```

Swapping provider is two variables — the client speaks the OpenAI-compatible protocol, which Groq, Gemini, OpenRouter and a local Ollama all serve.

## Before you go live

- [ ] **Rotate every demo account.** `admin`, `manager`, `hr`, `finance`, `auditor` and `employee1` all ship with the password `password`. Change them, or delete the ones you do not need, as your first action after the first deploy.
- [ ] **Generate a real `JWT_SECRET`** — `openssl rand -base64 48`. Never reuse the value in `.env.example`.
- [ ] **Set `CORS_ALLOWED_ORIGINS`** to your exact frontend origin.
- [ ] **Set `SPRING_PROFILES_ACTIVE=prod`**, which disables Swagger, tightens the login rate limit to 5/min and stops SQL logging.
- [ ] **Confirm `.env` is not committed** — it is gitignored; check `git status` before your first push.
- [ ] **Take database backups.** Free tiers rarely back up for you.

## Operational notes

**TLS.** Render, Railway and Fly all terminate TLS at their edge, so the app ships no keystore. `server.forward-headers-strategy: framework` is what makes Spring see the original `https` scheme behind the proxy.

**Migrations.** Flyway runs on every startup and is idempotent. `baseline-on-migrate` is on, so pointing at an existing database works. Because Hibernate runs at `validate`, a mapping that has drifted from a migration fails at boot rather than corrupting the schema.

**Memory.** The container sets `-XX:MaxRAMPercentage=75` instead of a fixed heap, so the JVM sizes itself to whatever the free tier grants — typically 512 MB.

**Cold starts.** A sleeping Render free service takes ~50s on the first request. If the demo needs to be instant, keep it warm with an external uptime pinger, or use Railway or Fly, which do not sleep.

**Health check.** `GET /api/health` is unauthenticated and checks the database connection, returning 200 when reachable and 503 when not. It also reports whether the AI path is enabled, so a deploy can be confirmed without logging in. `render.yaml` already points at it.
